**Время на выполнение:** 4 академических часа (2 пары) + самостоятельная работа.

## 1. Цель работы

Освоить применение математического аппарата метрик качества и строгой методологии тестирования ML-моделей. Научиться собирать индустриальные конвейеры (Pipeline) для предотвращения утечки данных (Data Leakage) и автоматизировать подбор гиперпараметров с помощью алгоритмов поиска.

## 4. Задачи для самостоятельной реализации

Опираясь на изученные в текущей и предыдущих лекциях инструменты, реализуйте следующий процесс:

1. **Инженерия данных и конвейеры обработки:**
    * Реализуйте `ColumnTransformer` для разделения потоков обработки признаков.
    * Числовые данные должны проходить через `SimpleImputer` для заполнения пропусков и `StandardScaler` для масштабирования.
    * Категориальные данные должны обрабатываться `SimpleImputer` (заполнение частым значением) и `OneHotEncoder` для перевода текста в бинарный формат.
    * Объедините шаги подготовки данных и алгоритм классификации/регрессии в единый объект `Pipeline`, чтобы гарантировать отсутствие утечек данных на этапе кросс-валидации.
2. **Кросс-валидация и гиперпараметры:**
    * Отложите 20% данных на независимый экзамен [Hold-out выборка].
    * Используйте `StratifiedKFold` для сохранения баланса классов при классификации или `KFold` для задачи регрессии.
    * Реализуйте подбор гиперпараметров (например, числа соседей или параметров леса) с помощью `GridSearchCV` (полный перебор по сетке) или `RandomizedSearchCV` [эффективный случайный поиск].
3. **Оценка бизнес-метрик и визуализация:**
    * *Для классификации:* Сформируйте матрицу ошибок [Confusion Matrix]. Выведите отчет `classification_report` с метриками Precision, Recall и F1-мерой. Оцените общее качество модели метрикой ROC-AUC.
    * *Для регрессии:* Рассчитайте квадратичные метрики (MSE, RMSE), метрику MAE (которая робастна к выбросам) и выраженную в процентах бизнес-метрику SMAPE.
    * Постройте визуализации: график распределения ошибок (остатков) для регрессии или графическое представление матрицы ошибок для классификации.
4. **Финальный экономический вывод:**
    * Опишите результаты простым бизнес-языком. Если это классификация: переведите ошибки I рода (FP) и II рода (FN) в потенциальные убытки бизнеса. Объясните, нужно ли менять жесткость алгоритма [баланс Precision/Recall].

5. Почему, согласно исследованиям Бергстра и Бенджио, `RandomizedSearchCV` во многих случаях эффективнее, чем педантичный `GridSearchCV`?
